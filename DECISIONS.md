## Standing rules — how to quote this log

One rule has no row: a run that would change a published result writes a sidecar
(`data/*_companyfilter.json`) instead of overwriting the file, so both results stay
reproducible from the same script. Same reason as the `.bak_old_labeler` files.

| # | decision | why |
|---|---|---|
| DATA-6 | Corpus grown in stages to 799 filings, the exact count of unique `(cik, report_year)` pairs across FinQA+ConvFinQA | Each growth adds distractors, so Arms 1-3 are re-run after every corpus change. One step was an accidental second ingest run with a different seed, caught only by a DB-vs-filesystem count. **Rule: verify corpus size against the DB or the filesystem, never a doc or memory** |
| INFRA-19 | The 9.4x loop-cost multiplier has no known source: **do not quote 9.4x -- re-derive it or drop it** | Searched 2026-09-03: nothing in `data/` or `scripts/` makes it; `git log -S` finds it only in a personal note. Near matches are coincidences `COST-24` marked suspect. No row asserts it, on purpose: inventing a source is worse than none |
| INFRA-21 | **Never publish a latency without the machine state beside it**, and diagnose with the right metric for the machine | Battery and heat were the wrong guess both times. Laptop: MPS kept freed memory (`AGENT-24`), invisible to `ps` RSS. AWS: CPU credits ran out (`DEPLOY-17`). Use `sysctl vm.swapusage` on the laptop, `CPUCreditBalance` on burstable instances -- never ps RSS, never pmset. Anything measured before 2026-09-05 inside a long pass is saturated-regime, not real latency |
| INFRA-22 | The recurring failure, twelve instances: **reusing a number, shape or file without checking which job produced it.** Check provenance before quoting, including your own | Instances: `compress.chunk_atoms` indexed replayed packer output with a Postgres `chunk_index`, returning wrong atoms silently (guarded 2026-09-07); `RETR-24` (B/C scored as A); `RETR-30` (GPU-hours anchored to the wrong job); `AGENT-16` (static rankings read in first-stage order); `GOLD-7`; `INFRA-17`; `AGENT-31` (stale replayed baseline); `AGENT-35` (`strip_entity_framing` fed a rewritten query); `RETR-50` (HNSW short at depth); `RETR-53` (two legs, different pools, one cell name); `AGENT-36` (Arm 6 inheriting `DEPLOY-25` defaults). ## Store and corpus

| # | decision | why |
|---|---|---|
| INFRA-1 | Store: Postgres + pgvector, not a dedicated vector DB (Pinecone/Weaviate/Qdrant) | Dedicated vector DBs win at hundreds-of-millions+ scale (sharding, ANN specialization). Our corpus is ~100k chunks — HNSW on one instance handles that. We also need hybrid search (dense + BM25 + relational metadata) in one SQL query, not 2-3 systems plus consistency glue |
| INFRA-2 | Docker image pinned to `pgvector/pgvector:0.8.6-pg18-trixie`, volume at `pgdata:/var/lib/postgresql` | Checked Aug 2026: Postgres 18 stable, 19 beta, 0.8.6 current pgvector. Full tag pinned so pgvector cannot drift. The old `.../data` mount crash-looped: Postgres 18+ needs the volume one level up for `pg_upgrade --link` |
| INFRA-4 | BM25 extension: `pg_search` (ParadeDB), not `ts_rank`, `VectorChord-bm25` or `pg_textsearch` | `ts_rank` isn't real BM25 (no length normalization or term saturation). `VectorChord-bm25` means leaving our image (`INFRA-2`); `pg_textsearch` has no package. `pg_search` ships a `.deb` for our base image. Query: `id @@@ paradedb.match(...)` in default OR-mode, i.e. IDF-weighted overlap, not require-all-terms |
| DATA-1 | Primary eval set: T²-RAGBench (`G4KMU/t2-ragbench`), not FinanceBench | FinanceBench: only 150 of 10,231 triples are public — too small to gate on (~4pt stderr at n=150). T²-RAGBench: 23,088 rows / 7,318 docs, fully open. FinanceBench kept as a secondary sanity check only |
| DATA-2 | ConvFinQA split 80/10/10 by document (`context_id`, seed 42), not by row | Ships with no split. Grouping by document rather than row stops the ~1.9 questions/doc from leaking one document across splits. Actual: 78.3/11.5/10.2 by row, zero cross-split docs |

## Chunking, and the heading fix

| # | decision | why |
|---|---|---|

| RETR-7 | Heading bug in `chunking._pack_atoms` fixed with boundaries not moved: each chunk now carries every heading its text sits under.
